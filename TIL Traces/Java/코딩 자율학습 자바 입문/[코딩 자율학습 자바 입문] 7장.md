# 7장 클래스
## 7.1 객체지향 프로그래밍
- 자바는 **객체지향 프로그래밍**
- 패러다임 : 프로그램을 설계하는 관점
  - 같은 프로그램을 만들더라도 패러다임에 따라 만드는 방식과 접근 방법이 달라짐

- 프로그래밍 패러다임
1. 명령형 프로그래밍(imperative programming) : 초기에 사용한 패러다임으로 프로그램의 상태와 제어 흐름을 조작하는 명령어를 순차적으로 실행하는 방식으로 설계함
  - 프로그램이 어떻게 동작하는지 제어하는데 초점이 맞춰져 있음
  - 순차적 처리가 중요
  - 명령어로 프로그램의 상태를 변경하고 제어문(조건문, 반복문)으로 명령어의 순서를 제어함
2. 객체 지향 프로그래밍(OOP, Object-Oriented Programming) : 데이터(상태 또는 속성)와 데이터를 조작하는 동작(기능)을 객체(object)라는 단위로 묶어 프로그램을 구성하는 방식
   - 객체 간에 서로 메시지를 전달해 상호작용하며 흐름을 제어함
   - 반복 코드가 줄어 재사용성이 높아지고 간결해짐
   - 프로그램이 유연하고 확장하기 쉬우며 유지 보수하기가 쉬움

<br> 

- 객체 프로그래밍의 특징 : 캡슐화, 상속, 다형성, 추상화
1. 캡슐화(encapsulation)
- 데이터와 동작 등 프로그램에 필요한 모든 자원을 객체로 묶어 감추는 것
- 객체의 데이터를 보호하고 외부에서 잘못된 접근을 못하게 막을 수 있음
- 캡슐 안에 가루 약이 숨어있는 것을 생각하면 됨

2. 상속(inheritance)
- 한 클래스의 데이터와 기능을 다른 클래스가 이어받는 것
- 상속을 통해 클래스끼리 부모 자식 관계가 생김

3. 다형성
- 동작이나 형태가 다른 기능을 하나의 이름으로 사용할 수 있게 하는 것
- 오버라이딩과 오버로딩을 통해 다형성을 지원함

4. 추상화
- 객체마다 데이터와 동작을 구체적으로 정의하지 않고 객체들의 공통적인 데이터와 동작만 추출해 선언하는 것 => 추상화 클래스
- 사전적으로 사물이나 개념에서 공통되는 특성이나 속성 따위를 추출해 파악하는 작용인 점에서 이름 지어짐  

## 7.2 클래스와 객체
- 클래스 : 자동차 설계도, 설계도로 여러 자동차를 만들 수 있듯 클래스를 기반으로 객체를 여러개 생성할 수 있음
- 객체 : 설계도로 구현한 자동차
![alt text](<클래스와 객체.png>)

### 7.2.1 클래스 선언
- 클래스 : 객체를 만들기 위한 설계도, 클래스는 객체가 있어야 사용할 수 있음
- 예외 : main() 메서드가 있는 클래스
  - main() 메서드가 있는 클래스는 객체를 생성하지 않고도 클래스를 사용할 수 있음

<br>

- 일반 클래스 만들기
1. 인텔리제이 프로젝트 창 > src > 마우스 우클릭 > New -> Package > 패키지명 작성
    - 패키지 : 클래스를 그룹화한 단위로 일종의 폴더
      - 패키지명은 모두 소문자로 작성
      - 숫자로 시작할 수 없음
      - _와 $ 외 특수문자는 사용할 수 없음
      - 키워드도 사용해선 안됨
2. 패키지 선택 > 마우스 우클릭 > New -> Java Class 선택 > Name 작성 > 엔터 > 편집기에 작성한 Name.java 파일이 열림
    - 해당 파일에 아래와 같이 작성되어있음
    ```java
    package ch07;

    public class Car {
    }
    ```
    - package = 패키지를 나타내는 키워드
      - 패키지를 나타내는 코드는 가장 위에 작성
      - import 문을 통해 다른 패키지의 클래스를 불러오면 패키지 아래에 추가됨
    - 그 아래에는 클래스 코드가 있고 클래스 코드 맨 앞에 있는 public은 **접근 제한자 또는 접근 제어자**라고 함
      - 접근 제한자 (접근 제어자) : 클래스에 접근할 수 있는 범위나 권한
        - 클래스의 경우 아무것도 붙이지 않거나 public을 붙이는 2가지만 가능
        - public은 같은 패키지에 있는 클래스 혹은 다른 패키지에 있는 클래스까지 다 접근 가능
        - 아무것도 붙이지 않은 패키지는 같은 클래스에서만 접근 가능
    - 접근 제한자 이후 클래스명이 나옴
      - 클래스명을 짓는 규칙은 변수명 짓는 규칙과 거의 동일
        - 첫 글자를 대문자로 짓기
      - 한 파일 안에 여러 클래스가 올 수 있지만 보통 자바 파일 하나에 클래스 하나라고 여겨짐

### 7.2.2 클래스 멤버
- 클래스의 멤버 : 클래스에 3가지 구성 요소
1. 필드 (field) 또는 멤버 변수 (memer variable)
   - 클래스에 선언하는 변수
   - 필드는 객체의 데이터에 해당하는 상태나 속성을 저장할 때 사용함
   - 필드에도 접근 제한자를 사용할 수 있음
    - #### 필드의 3가지 변수  
     1. 인스턴스 변수 (instance variable) : 클래스가 객체를 생성할 때마다 새로 생성되는 변수
        - 객체마다 각각 고유한 값이 저장됨
        - 클래스에서 선언하지만 객체에서 각각 고유한 값으로 초기화됨
     2. 클래스 변수 (class variable) : 클래스로 생성한 모든 객체에서 공유하는 변수
        - 클래스 변수를 선언할 때는 앞에 **static** 키워드를 붙임
        - 클래스에서 한번만 초기화하고 모든 객체에서 같은 값을 사용함
        - 객체에서 공통으로 사용할 데이터가 필요하면 클래스 변수에 저장
     3. 지역 변수 (local variable) : 메서드에 선언하는 변수
        - 메서드가 실행될 동안만 지역 변수에 저장된 값이 유효함

   - 예시
     - 자동차를 브랜드, 연식, 색으로 구분
     - 생한한 자동차 수량을 관리
     - 수량, 브랜드, 연식, 색은 자동차 상태를 나타내므로 **필드**로 선언
     - 브랜드, 연식, 색은 생산한 자동차마다 달라질 수 있으므로 **인스턴스 변수**
     - 자동차 수량은 클래스에서 생성한 객체의 수 => 객체가 아닌 클래스 단위로 관리해야하기 때문에 **클래스 변수**
        ```java
        package ch07;

        public class Car {
        //    클래스 변수
            static int countOfCars = 0; // 자동차 수량
        //    인스턴스 변수
            String brand; // 브랜드
            int year; // 연식
            String color; // 색
        }
        ```
<br>

2. 메서드
    - 함수 : 특정 작업을 여러번 수행해야 할 때 해당 작업을 수행하는 코드를 정의해두고 가져와서 사용할 있게 하는 코드 블록
    - 메서드 : 클래스 안에 정의한 함수
      - 프로그래밍에서는 함수와 메서드를 구분하지만 **자바에서는 모든 함수가 클래스 안에 정의**되므로 같은 개념으로 여김
      - 자바에서는 함수를 모두 메서드라고 함
      - 뻥튀기 기계에 비유할 수 있음
        - 값(옥수수)를 입력 받아 메서드(뻥튀기 기계가) 작동해서 결괏값(뻥튀기)를 내놓는 것
        - ![alt text](<메서드 작동 원리.png>)
    - 메서드의 기본 형식
        ```java
        [접근 제한자] 반환형 메서드명(매개변수1, 매개변수2, ...){
            메서드 본문
        }
        ```
        - 메서드도 접근 제한자를 통해 접근 범위를 제한할 수 있음
          - 아무것도 명시하지 않으면 같은 패키지 안에서만 접근할 수 있음
        - 반환형 (return type) : 메서드를 실행한 뒤 결과로 어떤 자료형의 값을 반환할지 선언하는 것
          - 생략할 수 없음
          - 결과를 돌려줄 필요가 없으면 void 키워드로 선언
          - void로 선언하지 않았다면 항상 결과를 반환해야함
          - return 이후 반환하게 되는데 이를 반환값이라고 함
          - 반환값은 메서드 이름 앞에 선언한 반환형과 자료형이 같음
        - 반환형 이후 메서드 명이 옴
          - 메서드명은 메서드가 어떤 동작을 하는지 드러나게 지어야 함
          - 카멜 표기법에 따라 첫글자를 소문자로 시작함
            - 첫 단어를 제외하고는 각 단어의 첫글자를 대문자로 표기
        - 소괄호 안 매개변수
          - 메서드가 외부에서 전달받는 값을 저장하는 변수
          - 매개변수의 자료형은 전달 받은 값의 자료형과 같아야 함
          - 메서드는 전달받은 값을 사용해 명령을 수행하고 값을 전달한 곳에 결과를 돌려줌
          - 매개변수는 없을 수도 있고 여러개일 수도 있음
          - 없는 경우 빈 괄호만 표시
          - 매개변수는 메서드 내에서만 유효한 지역 변수임
        - 메서드 시그니처 : 반환형과 매개변수를 합쳐 부르는 이름
          - 메서드 시그니처는 메서드를 식별할 수 있는 고유의 정보를 담고 있음
          - 메서드 시그니처 뒤에 중괄호로 감싼 메서드 본문이 나옴 => 이를 메서드 정의라고 함

    <br>

    - 예시 : Car 클래스에서 자동차 정보를 출력하는 메서드 정의
        ```java
        Pupackage ch07;

        import java.time.Year;

        public class Car {
        //    클래스 변수
            static int countOfCars = 0; // 자동차 수량
        //    인스턴스 변수
            String brand; // 브랜드
            int year; // 연식
            String color; // 색
        //    인스턴스 메서드
            public void carInfo(){
                System.out.println("---자동차 정보---");
                System.out.println("브랜드: " + brand);
                System.out.println("연식: " + year);
                System.out.println("색: " + color);

            }
        //    클래스 메서드
            public static void countOfCarsInfo(){
                System.out.println("자동차 수량: " + countOfCars);
            }
        }

        ```
          - void로 선언하여 결과를 반환하지 않음
          - 인스턴스 메서드 : 인스턴스 변수에 접근
          - 클래스 메서드 : 클래스 변수에 접근
            - 인스턴스 변수나 인스턴스 메서드에 접근할 수 없음
            - static 키워드를 넣어 선언함
            - 정적 메서드라고도 함

    - 메서드 호출 : 정의한 메서드를 실행하는 것
        ```java
        메서드명(인자1, 인자2,...)
        ```
        - 인자 : 매개변수가 있는 메서드를 호출할 때 매개변수에 전달하는 값
        - 메서드를 호출하면 메서드 본문이 실행되며 특정 작업을 수행하게 되고 이때 사용할 데이터를 제공
        - 매개변수가 없는 변수 호출 시에는 인자가 필요 없음

3. 생성자
    - 생성자 : 객체를 생성하고 초기화하는 특별한 메서드
    - 객체가 생성될 때 자동으로 실행되며 생성된 객체의 초깃값을 설정하는데 사용
    - 생성자는 클래스와 이름이 같고 반환형을 명시하지 않음
      - 반환형을 명시하면 일반 메서드가 됨
    - 생성자 본문에는 개체를 초기화하는 내용이 들어감
    - 클래스가 생성자를 정의하지 않으면 컴파일러가 자동으로 생성자를 추가함
      - 자동으로 생성한 생성자는 매개변수가 없음 => 기본 생성자라고 함
      - 기본 생성자를 직접 정의할 수도 있음
    - 기본 생성자 예시
        ```java
        package ch07;

        import java.time.Year;

        public class Car {
        //    클래스 변수
            static int countOfCars = 0; // 자동차 수량
        //    인스턴스 변수
            String brand; // 브랜드
            int year; // 연식
            String color; // 색
        //    기본 생성자
            public Car(){
                System.out.println("새로운 자동차 객체가 생성됐습니다.");
            }
        //    인스턴스 메서드
            public void carInfo(){
                System.out.println("---자동차 정보---");
                System.out.println("브랜드: " + brand);
                System.out.println("연식: " + year);
                System.out.println("색: " + color);

            }
        //    클래스 메서드
            public static void countOfCarsInfo(){
                System.out.println("자동차 수량: " + countOfCars);
            }
        }

        ```
    - 클래스 안에서 기본 생성자 외에 생성자 여러 개를 정의할 수 있음
      - 각 생성자의 매개변수가 달라야 구분할 수 있음
      - 매개변수가 있는 생성자를 사용하면 객체의 초깃값을 원하는 대로 설정할 수 있음

    - 생성자 예시
        ```java
        package ch07;

        import java.time.Year;

        public class Car {
        //    클래스 변수
            static int countOfCars = 0; // 자동차 수량
        //    인스턴스 변수
            String brand; // 브랜드
            int year; // 연식
            String color; // 색
        //    기본 생성자
            public Car(){
                System.out.println("새로운 자동차 객체가 생성됐습니다.");
                //    인스턴스 메서드 호출
                this.carInfo();
            }

        //    매개변수 2개 있는 생성자
            public Car(String brand, int year){
                System.out.println("새로운 자동차 객체가 생성됐습니다.");
                this.brand = brand;
                this.year = year;
                this.color = "white";
                this.carInfo();
            }

        //    매개변수가 3개 있는 생성장
            public Car(String brand, int year, String color){
                System.out.println("새로운 자동차 객체가 생성됐습니다.");
                this.brand = brand;
                this.year = year;
                this.color = color;
            }

        //    인스턴스 메서드
            public void carInfo(){
                System.out.println("---자동차 정보---");
                System.out.println("브랜드: " + brand);
                System.out.println("연식: " + year);
                System.out.println("색: " + color);

            }
        //    클래스 메서드
            public static void countOfCarsInfo(){
                System.out.println("자동차 수량: " + countOfCars);
            }
        }

        ```
        - this 키워드 : 객체 자신, 즉 생성자를 호출해서 생성한 객체를 가리키는 특별한 변수
        - this 사용 방법  
            1. 객체에서 인스턴스 변수와 매개변수의 이름이 같을 때 둘을 구분하는데 사용
                - 두번째 생성자를 보면 매개변수로 받은 값을 객체의 인스턴스 변수에 저장함
                - 인스턴스 변수와 매개변수의 이름이 같을 때 인스턴스 변수에 this를 붙이면 구분 가능
            2. 객체의 메서드를 호출할 때 사용
                - 점 연산자(.)로 this와 메서드를 연결하면 객체의 인스턴스 메서드를 호출하게 됨
                - 점 연산자 : 멤버 참조 연산자, 객체의 변수나 메서드에 접근할 때 사용

### 7.2.3 객체 생성
- 객체 생성 시 new 키워드 사용
- 형식
    ```java
    new 클래스명();
    ```
    - 해당 클래스에 정의한 생성자를 호출하며 객체를 생성함
    - 클래스명()이 사실상 생성자를 호출하는 것
- 예시 : Car 클래스 객체 생성하기
    ```java
    new Car();
    ```
    - 객체를 생성하면 메모리 어딘가에 저장됨
    - 객체를 생성하고 난 이후 사용하려면 변수에 객체의 저장 위치를 할당해야함
    - 객체를 받는 변수의 자료형은 객체를 생성한 클래스가 됨
        ```java
        클래스명 변수명 = new 클래스명();
        ```
        - 변수에 저장되는 것은 클래스 객체가 있는 위치인 메모리 주소
        - 객체도 배열과 마찬가지로 참조 주소를 사용함

<br>

- new 키워드를 사용한 객체 생성과 참조
![alt text](<런타임 데이터 영역의 구조.png>)
    - 메서드 영역 : 프로그램이 시작될 때 클래스 관련 정보가 저장되는 공간
      - 클래스 명, 부모 클래스, 클래스 변수와 필드 정보(필드명, 자료형 등), 메서드 정보(메서드명, 반환형, 접근 제한자 등), 메서드 코드 등이 저장됨
      - 프로그램이 시작될 때 메모리에 로드되고 프로그램이 종료될 때까지 유지됨
      - 메서드 영역에 저장된 정보는 클래스의 모든 객체에 공유됨
    - 힙 : 프로그램이 실행되며 동적으로 생성된 객체와 배열이 저장되는 공간
      - 객체와 함께 인스턴스 변수들도 저장됨
      - new 키워드로 생성하면 힙 영역에 저장됨
    - 스택 : 메서드 실행과 관련한 정보들이 저장되는 공간
      - 지역 변수(일반 변수, 참조 변수 모두 해당), 메서드 결과 반환 주소 등이 해당됨
      - 메서드가 실행될 때 자동으로 메모리가 할당되고 메서드가 종료되면 해제됨
    - JVM의 구성요소 중 하나인 클래스로더가 클래스 파일을 메모리로 불러오는 것을 로드(Load)라고 함

    - 객체는 힙에 참조 변수는 스택에 할당됨
      - 참조 변수는 객체의 메모리 주소를 저장
      - 저장된 주소를 참조해 객체에 접근하는 방식을 취함
      - 스택에 주소가 들어가고 이걸 참조해 힙에 있는 값을 가져옴
        ![alt text](<new 키워드를 사용한 객체 생성과 참조.png>)

### 문자열 리터럴과 new 키워드의 차이
- 문자열 리터럴
    ```java
    String str1 = "Hello"
    ```
    - 객체가 문자열 상수 풀에 생성됨
    - 문자열 상수 풀은 무자열 리터럴이 저장되는 곳으로 힙에 있는 특수한 영역
    - 문자열 리터럴로 객체를 생성하면 JVM이 문자열 상수 풀에 해당 문자열 리터럴이 저장되어있는지 확인
    - 저장되어있으면 기존 객체 사용, 없으면 새로운 객체 생성

    ![alt text](<문자열 상수 풀 참조.png>)
    - 같은 문자열을 저장했기 때문에 동일한 객체를 참조
    - == 연산자로 비교 시 출력 결과 `true`

<br>

- new 키워드
  - 문자열 상수 풀에서 값을 찾는 것이 아니라 **힙에서 새로운 객체 생성**
  - str1, str3은 완전 다른 객체로 ==을 사용했을 때 `false`가 나옴
    ![alt text](<문자열 리터럴과 new 키워드 차이.png>)

<br>

- == 연산자는 두 문자열 객체가 **동일한 위치**를 가르키는지를 확인
- 두 문자열의 내용, 즉 값을 비교하고 싶다면 equals() 메서드를 사용
```java
String str1 = "Hello";
String str2 = "Hello";
String str3 = new String("Hello");
System.out.println(str1 == str2); // 출력: true
System.out.println(str1 == str3); // 출력: false
System.out.println(str1.equals(str2)); // 출력: true
System.out.println(str1.equals(str3)); // 출력: true
```
