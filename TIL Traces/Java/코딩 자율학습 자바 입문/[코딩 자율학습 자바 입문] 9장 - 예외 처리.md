# 9장 예외 처리
## 9.1 오류와 예외
### 9.1.1 오류
- 오류 : 프로그램에서 발생할 수 있는 심각한 문제로 제어할 수 없고 정상적인 실행도 불가능한 상황
  - 오류가 발생하면 프로그램이 컴파일되지 않음
  - 어떤 오류는 프로그램이 실행될 때까지 확인되지 않는 경우도 있음
    - 코드를 작성하고 컴파일하기 전 혹은 실행하기 전 오류를 제거해야함

- 오류 유형
1. 컴파일 타임 오류 (compile time error)
  - 컴파일 과정에서 컴파일러가 이해할 수 없는 코드가 있을 때 발생하는 오류
    - 문법 오류 : 오타 혹은 세미콜론 누락 등 문법에 맞지 않게 코드 작성한 경우
    - 타입 오류 : 잘못된 자료형을 사용하는 오류
    - 참조 오류 : 선언하지 않은 변수나 메서드 사용 시

2. 런타임 오류 (runtime error)
   - 프로그램 실행 중 처리할 수 없는 연산을 만나 비정상적으로 종료되는 경우
   - 문법 오류가 아니라서 컴파일 타임에는 문제가 발생하지 않음
   - 잘못된 값을 입력하거나 존재하지 않는 파일에 접근하거나 무한 루프에 빠져 메모리 문제가 발생하는 경우 해당됨  
    => `예외 처리를 통해 해결할 수 있음`
   - 프로그램을 실행하는 중 장치에 문제가 생기는 경우에도 런타임 오류가 발생할 수 있음

3. 논리 오류 (logical error)
   - 컴파일과 실행은 정상적으로 되지만 결과가 의도한 대로 나오지 않아 발생하는 오류
     - 예 : 결과가 양수로 나와야 하는데 음수로 나오거나 변수 a의 값이 나와야 하지만 a+b가 나오는 등의 경우
   - 문법적으로 문제가 없어서 컴파일러가 오류를 잡아주지 못하고 개발자가 직접 오류를 찾아 수정해야 해서 해결이 어려움

- 버그와 디버깅
  - 버그 : 프로그램이 의도한대로 작동하지 않거나 갑자기 실행이 중단되며 오작동하는 것
  - 디버그 : 버그의 원인을 찾아 수정하는 작업

### 9.1.2 예외
- 예외 (exception) : 예측할 수 있는 오류
- 예외 처리 (exception handling) : 예외를 미리 조치를 취하는 것
  - 프로그램을 실행할 때 발생할 수 있는 예외에 대비한 코드를 미리 작성해 프로그램이 비정상적으로 종료하는 것을 막고 프로그램이 계속 실행될 수 있게 하는 작업
  - 자바에서 발생하는 예외는 컴파일러가 예외 처리를 확인하는지 안 하는지에 따라 `확인 예외`와 `미확인 예외`로 나뉨

- 확인 예외 : 컴파일러가 자바 소스 코드를 컴파일하는 과정에서 예외를 확인하고 예외 처리하는지 검사
  - 예외 처리하지 않으면 컴파일 오류가 발생 => `컴파일 예외`라고도 함
- 미확인 예외 : 컴파일 과정에서 예외 처리를 확인하지 않으며 명시적으로 예외 처리하도록 강제하지도 않음
  - 런타임에 발생하므로 `런타임 예외` 라고도 함

- 자바에서 예외를 다룰 수 있는 클래스
![alt text](<예외 클래스의 구조.png>)
  - `Throwable class` : 최상위 클래스

  - `Exception class` : Throwable 클래스를 상속받음
    - Exception class를 상속 받는 클래스 : 잘못된 입력이나 로직처럼 코드 자체에서 발생하는 문제를 다룸, `확인 예외`(컴파일러가 예외 처리를 강제)와 `미확인 예외`를 포함
      - IOException : 파일, 모니터, 키보드 등의 장치에서 읽기/쓰기 중에 발생
      - ClassNotFoundException : 객체 생성 시 해당 클래스를 찾을 수 없을 때 발생
      - FileNotFoundException : 파일 입출력 작업을 할 때 지정된 경로에 파일이 존재하지 않거나 접근할 수 없을 때 발생
      - `RuntimeException` : Exception 클래스를 상속하지만 `미확인 예외`에 속함, 런타임에서 발생하는 예외로 `실행 조건`에 따라 발생할 수도 있고 발생하지 않을 수도 있는 예외, 컴파일 과정에서 확인할 수 없고 프로그램이 실행되는 과정에서 발생하며 예외 처리를 강제하지 않음
        - ArithmeticException : 0으로 나누기처럼 산술 연산에서 발생
        - NullPointerException : null 값 참조로 필드나 메서드에 접근할 때 발생
        - ArrayIndexOutOfBoundsException : 잘못된 인덱스로 배열 요소에 접근할 때 발생
        - IllegalArgumentException : 잘못된 값이 메서드에 전달되면 발생
        - InvalidFormatException : 데이터 형식이 유효하지 않을 때 발생
        - NumberFormatException : 문자열을 숫자로 변환할 때 형식이 유효하지 않으면 발생

  - `Error class` : Throwable 클래스를 상속받음
    - Error class를 상속 받는 클래스 : 자바 프로그램이 실행되는 JVM 환경에서 발생하는 문제를 다룸, 가상 머신과 메모리 같은 코드 외적인 부분에서 발생하므로 개발자가 처리하기 어려운 경우가 많음, `미확인 예외`에 속하며 일반적으로 프로그램에서 처리하지 않고 `프로그램이 종료됨`
      - OutOfMemoryError : JVM의 메모리가 부족할 때 발생함
      - StackOverflowError : 스택 메모리가 초과될 때 발생
      - VirtualMachineError : JVM에서 발생하는 심각한 오류를 나타냄
      - LinkageError : 클래스의 링크 과정 (프로그램이 실행되기 전에 클래스 파일이 JVM에 의해 준비되는 과정)에 문제가 있을 때 발생

- null 값 참조
  - 자바에서 변수를 선언할 때 값을 초기화하지 않으면 기본값으로 설정됨
  - 각 자료형의 기본값
    - int = 0
    - boolean = false
    - 참조형 = null
  - null은 0이나 공백이 아니라 `값 자체가 없다는 것`을 나타내는 키워드
    - 참조형으로 선언된 변수는 값이 직접 저장된 것이 아니라 `값이 저장된 메모리 주소를 저장함`
    - 참조 변수가 null로 초기화된다는 것은 `저장된 주소가 없다는 것`을 의미함 (아무것도 가리키고 있지 않다는 것)
  - null 값을 가진 변수로 필드나 메서드에 `접근`하는 것을 `null 값 참조`라고 함 => NullPointerException이 발생함

## 9.2 예외 처리하기
### 9.2.1 try-catch-finally 문으로 예외 처리하기
```JAVA
try {
  // 예외가 발생할 수 있는 코드
} catch (예외_클래스 변수){
  // 해당 예외가 발생했을 때 수행할 동작
} finally {
  // 예외와 상관없이 항상 수행할 동작
}
```
- try 블록 안 : 예외가 발생할 수 있는 코드 작성
  - 예외가 발생하면 이후 코드는 실행하지 않고 `catch` 블록으로 넘어감
- catch 블록 안 : try 블록에서 예외가 발생했을 때 실행
  - 어떤 예외가 발생할지 정의하고 이를 처리하는 코드를 작성
  - 여러개 작성해 다양한 예외 처리를 할 수 있음
  - try 블록에서 작성한 예외와 일치하는 catch 블록이 없으면 예외 처리를 하지 못하고 프로그램 종료
- finally 블록 안 : 필수 요소는 아니지만 예외와 상관없이 무조건 실행해야 하는 코드가 있을 때 작성
  - 메모리 등 자원을 해제하거나 정리 작업을 수행하는데 사용됨
  - try 블록에서 예외가 발생하지 않으면 try 블록을 수행한 후 finally 블록으로 넘어감

<br>

- 예제 : 0으로 나누는 예외 상황 - ArithmeticException
```JAVA
package c09;

import java.util.Scanner;

public class TryCatchExample {
    public static void main(String[] args){
        Scanner scan = new Scanner(System.in);
        System.out.println("첫번째 정수를 입력하세요.");
        int a = scan.nextInt();
        System.out.println("두번째 정수를 입력하세요.");
        int b = scan.nextInt();
        try {
            int result = a/b;
            System.out.println("결과: "+result);
        } catch (ArithmeticException e){
            System.out.println(e);
        } finally {
            System.out.println("프로그램을 종료합니다.");
        }
    }
}
```
- 실행 결과
```JAVA
첫번째 정수를 입력하세요.
10
두번째 정수를 입력하세요.
0
java.lang.ArithmeticException: / by zero
프로그램을 종료합니다.

```
- try 블록에서 예외가 발생하면 발생한 예외 정보를 `e 객체`에 저장
- 예외 객체는 catch 블록으로 보내고 예외 이루 코드는 수행하지 않음
- try 블록에서 보낸 예외 객체가 catch 블록에 정의된 예외와 일치하면 catch 블록 안의 내용을 수행
  - ArithmeticException은 예외 클래스, e는 매개변수
  - try에서 발생한 예외 정보는 오류 메세지와 동일함
- finally 블록에 있는 문장을 실행하고 프로그램을 종료함

### 9.2.2 throw로 예외 발생시키기
- `throw`를 통해 의도적으로 예외를 발생시킬 수 있음
  - RuntimeException 예외를 처리할 때 주로 사용됨
- 형식
  ```JAVA
  throw new 예외_클래스([예외_메시지]);
  ```
  - 예외 발생 시 예외 메시지가 출력됨

- 예시 : 3으로 나눌 때 예외가 발생하게 만드는 경우
  ```JAVA
  package c09;

  import java.util.Scanner;

  public class TryCatchExample {
      public static void main(String[] args){
          Scanner scan = new Scanner(System.in);
          System.out.println("첫번째 정수를 입력하세요.");
          int a = scan.nextInt();
          System.out.println("두번째 정수를 입력하세요.");
          int b = scan.nextInt();
          try {
              if (b==3){
                  throw new ArithmeticException("3으로 나눌 수 없습니다!");
              }
              int result = a/b;
              System.out.println("결과: "+result);
          } catch (ArithmeticException e){
              System.out.println(e.getMessage());
          } finally {
              System.out.println("프로그램을 종료합니다.");
          }
      }
  }

  ```
  - 실행 결과
    ```JAVA
    첫번째 정수를 입력하세요.
    10
    두번째 정수를 입력하세요.
    3
    3으로 나눌 수 없습니다!
    프로그램을 종료합니다.
    ```

- 프로그램을 실행하면 컴파일러가 알아서 예외를 확인함
- throw 키워드는 개발자가 일부러 예외를 발생시키고 이를 catch 블록으로 던져 컴파일러가 확인하게 하는 것
- catch 블록 안 getMessage() 메서드는 Throwable 클래스에 속한 머서드로 예외가 발생할 때 표시하는 예외 메시지를 문자열로 반환함
- printStackTrace() 메서드는 발생한 예외의 출처를 메모리에서 추적해 예외가 발생한 위치를 단계별로 출력해줌


### 9.2.3 `throws`로 예외 처리 넘기기
- `throws` 키워드 : 예외 처리를 다른 곳으로 넘길 때 사용
  - 해당 메서드에서 예외를 처리하지 않고 호출한 곳에서 처리함
  - 예외를 발생시킬 때 사용한 throw와 비슷해보나 s가 붙고 다름

- 형식
  ```JAVA
  반환명 메서드명(매개변수) throws 예외_클래스 {
    // 수행할 내용
  }
  ```

- 예시
``` java
package c09;

import java.io.BufferedReader;
import java.io.File;
import java.io.FileReader;
import java.io.IOException;

public class ThrowsExample {

    public static void main(String[] args){
        try {
            readFile("/Users/sarah/Desktop/Coding/SSAFY/SSAFY Data/SSAFY_study/TIL/TIL Traces/Java/코딩 자율학습 자바 입문/example.txt"); // 파일 읽기 메서드 호출
        } catch (IOException e){
            System.out.println(e);
        } finally {
            System.out.println("프로그램을 종료합니다.");
        }
    }

    // 예외 처리를 호출한 곳으로 넘김
    // readFile 메서드
    // IOException : FileNotFoundException와 같이 읽으려는 파일이 존재하지 않는 등의 오류가 발생할 수 있지만 상위 예외 클래스인 IOException만 적어도 모두 대응하게 됨
    public static void readFile(String fileName) throws IOException {
        // 파일을 읽기 위해 객체 생성
        File file = new File(fileName);
        // FileReader = 파일을 문자 단위로 읽는 클래스
        // BufferedReader = 버퍼(기본 8KB)를 사용해 한번에 많은 데이터를 읽어올 수 있는 클래스
        // file 객체를 FileReader로 읽어 FileReader를 객체를 생성하고 이를 BufferedReader 클래스에 전달
        // BufferedReader 클래스는 객체를 생성하고 FileReader 객체에 있는 데이터를 버퍼에 저장
        BufferedReader reader = new BufferedReader(new FileReader(file));
        // 버퍼에서 데이터를 한줄씩 가져와서 저장, 파일 끝에 도달하면 null을 반환
        String line = reader.readLine();

        // line에 저장된 주소가 null일 때까지 반복
        while (line != null){
            // 저장된 한줄을 출력하고
            System.out.println(line);
            // 다음줄을 다시 line에 저장
            line = reader.readLine();
        }
        // 다 읽었으면 버퍼를 닫아줌
        reader.close();
    }
}
```

- 실행 결과
``` java
throws test
프로그램을 종료합니다.
```
- `throw`와 `throws`의 차이점
  - throw는 사실 상 try-catch 안에서 예외를 발생시킴
  - throws는 메서드가 따로 있고 그 메서드를 호출한 try-catch 안에서 예외를 발생시킴

## 셀프체크
``` java
package c09;

import java.util.Scanner;

// 예외 클래스를 상속받음
class LowBalanceException extends Exception { // 사용자 정의 예외 클래스
    public LowBalanceException(String message) {
        super(message);
    }
}
class BankAccount { // 입출금 계좌 클래스
    private double balance;
    public BankAccount(double initialBalance) {
        this.balance = initialBalance;
    }
    public void deposit(double amount) {
        balance += amount;
        System.out.println(amount + "원이 입금됐습니다.");
        System.out.println("현재 잔액: " + balance + "원");
    }
    public void withdraw(double amount) throws LowBalanceException {
        System.out.println(amount + "원을 출금합니다.");
        if (amount > balance) {
            throw new LowBalanceException("잔액이 부족합니다.");
        }
        balance -= amount;
        System.out.println(amount + "원이 출금됐습니다.");
        System.out.println("현재 잔액: " + balance + "원");
    }
    public double getBalance() {
        return balance;
    }

    public static void main(String[] args){
        BankAccount myBank = new BankAccount(0);
        Scanner scan = new Scanner(System.in);
        try {
            int input = scan.nextInt();
            myBank.deposit(input);

            int output = scan.nextInt();
            myBank.withdraw(output);
        } catch (LowBalanceException e){
            System.out.println("오류: " + e.getMessage());
        } finally {
            System.out.println("현재 잔액: " + myBank.getBalance());
        }
    }
}
```
