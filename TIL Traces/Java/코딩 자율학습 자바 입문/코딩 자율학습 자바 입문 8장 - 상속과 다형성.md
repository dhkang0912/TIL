# 8장 상속과 다형성
## 8.1 상속
### 8.1.1 상속이란
- 상속 : 한 클래스가 다른 클래스의 필드와 메서드를 이어받아 사용하고 기능을 확장할 수 있는 개념
  - 상속 받은 자식 클래스는 부모 클래스에 작성된 내용을 물려받아 재사용할 수 있으므로 중복되는 필드나 메서드를 줄일 수 있는 장점이 있음
  - 부모 클래스 (상위 클래스, 슈퍼 클래스) : 상속하는 클래스
  - 자식 클래스 (하위 클래스, 서브 클래스) : 상속받는 클래스
- 형식
```java
class 자식_클래스명 extends 부모_클래스명 {
    // 클래스 본문
}
```
- 예시
```java
class Animal {}
class Dog extends Animal {}
class Cat extends Animal {}
```
    - Dog와 Cat 클래스가 Animal이라는 클래스를 상속받는 경우

### 8.1.2 실습: 클래스 상속하기
#### ✔︎ 일반 클래스
- Dog 클래스
    ```java
    package ch08;

    public class Dog {
        String breed; // 견종
        String name; // 이름
        int age; // 나이

    //    메서드
        public void eat(){
            System.out.println(name + "가 밥을 먹습니다.");
        }
        public void roll(){
            System.out.println(name + "가 바닥을 구릅니다.");
        }
    }

    ```

- Cat 클래스
    ```java
    package ch08;

    public class Cat {
        String name;
        int age;
        public void eat(){
            System.out.println(name + "가 밥을 먹습니다.");
        }

        public void rub(){
            System.out.println(name + "가 몸을 비빕니다.");
        }
    }

    ```
=> name, age, eat() 이라는 메서드가 공통적으로 들어감, 부모 Animal 클래스를 만들어서 상속할 수 있음

#### ✔︎ 상속
- Animal 클래스 (부모 클래스)
    ```java
    package ch08;

    public class Animal {
        // 필드
        String name;
        int age;
        // 메서드
        public void eat(){
            System.out.println(name + "가 밥을 먹습니다.");
        }

    }
  ```

- Dog 클래스 (자식 클래스)
    ```java
    package ch08;

    public class Dog extends Animal{
        String breed; // 견종

        public void roll(){
            System.out.println(name + "가 바닥을 구릅니다.");
        }
    }

    ```

- Cat 클래스 (자식 클래스)
    ```java
    package ch08;

    public class Cat extends Animal{
        public void rub(){
            System.out.println(name + "가 몸을 비빕니다.");
        }
    }

    ```

- Main 클래스
```java
package ch08;

public class Main {
    public static void main(String[] args){
        // Dog, Cat, Animal 클래스 모두 명시적 생성자가 없으므로 기본 생성자가 추가되고 필드가 초기화됨

        Cat myCat = new Cat();
        myDog.breed = "진돗개";
        myDog.name = "바둑이";

        myCat.name = "나비";
        myCat.age = 2;
        System.out.printf("%S는 %d살입니다.", myCat.name, myCat.age);

        myDog.eat();
        myDog.roll();
        myCat.eat();
        myCat.rub();
    }
}
```

## 8.2 다형성
### 8.2.1 메서드 오버라이딩
- 메서드 오버라이딩 (method overriding) : 자식 클래스에서 다른 동작을 수행하도록 메서드를 변형해서 사용하는 것 => 상속받은 메서드를 재정의하는 것
  - 부모 클래스의 메서드를 자식 클래스에 오버라이딩하기 위한 조건 : 메서드와 이름, 반환형, 매개변수의 개수와 순서, 자료형이 모두 부모 클래스와 동일해야 함
  - Cat 클래스 오버라이딩
    ```java
    package ch08;

    public class Cat extends Animal{
        public void rub(){
            System.out.println(name + "가 몸을 비빕니다.");
        }

        public void eat(){
            System.out.println(name + "가 닭고기를 먹습니다.");
        }
    }
    ```

  - 실행 결과
    ```java
    바둑이는 진돗개이고 3살입니다.
    나비는 2살입니다.바둑이가 밥을 먹습니다.
    바둑이가 바닥을 구릅니다.
    // 오버라이딩되어 밥 -> 닭고기로 바뀜
    나비가 닭고기를 먹습니다.
    나비가 몸을 비빕니다.
    ```
    - Animal 클래스에 정의한 eat() 메서드가 아닌 Cat 클래스에서 정의한 eat() 메서드가 실행됨
    - 자식 클래스에서 부모 클래스를 재정의하면 (오버 라이딩하면) **자식 클래스의 메서드에 우선순위**가 있음
    - Dog 클래스에서는 오버라이딩하지 않아 여전히 밥을 먹는다로 출력되는 것을 볼 수 있음  
    => **메서드 오버라이딩을 통해 같은 메서드를 객체마다 다르게 동작** -> **다형성** 구현

- 다형성 : 하나의 객체나 메서드가 여러 형태로 사용될 수 있는 특성

#### ✔︎ 애너테이션
- 애너테이션 : 자바에서 메타데이터 (데이터에 대한 부가 정보)를 클래스, 메서드, 변수 등에 추가하는 방법
  - 사전적인 의미 : 주석
  - 코드에 대한 설명이나 문법을 컴파일러가 확인하도록 정보를 제공하는 기능
  - 코드의 의미를 명확하게 해서 코드의 가독성을 높이고 유지보수를 용이하게 함

- @Override 애너테이션 : 오버라이딩을 명시적으로 나타낼 수 있음
  - 예시
      ```java
      public class Cat extends Animal { 
          public void rub() {
              System.out.println(name + "가 몸을 비빕니다.");
          }
          @Override // 오버라이딩 애너테이션
          public void eat() { // 메서드 오버라이딩
              System.out.println(name + "가 닭고기를 먹습니다.");
          }
      }
      ```

- 표준 애너테이션 : 자바 표준 라이브러리에 포함된 애너테이션
  - @override, @Deprecated (더 이상 사용되지 않음)
- 메타 애너테이션 : 애너테이션을 위한 애너테이션, 다른 애너테이션을 정의할 때 사용
  - @Retention, @Target
- 커스텀 애너테이션 : 사용자가 직접 정의한 애너테이션

### 8.2.2 메서드 오버로딩
- **오버로딩** : 메서드명은 같지만 매개변수의 개수와 순서, 자료형이 다른 메서드를 같은 클래스 안에 여러개 정의하는 것
  - **메서드를 확장하여 다형성을 구현**
    - 생성자가 메서드 시그니처에 따라 다르게 초기화 됐던 것 역시 오버로딩
    - 오버로딩은 메서드 시그니처에 따라 메서드가 다르게 동작함  
    => **변수와 자료형이 다른 메서드를 여러 개 정의하는 것**  
    => 한 클래스 안에서 일어남  
    => 매개변수의 개수나 순서, 자료형이 다름
- **오버라이딩** : 메서드명, 반환형, 매개변수의 개수와 순서까지 모두 같지만 동작만 다른 메서드를 자식 클래스에 정의하는 것  
  - **메서드가 객체마다 다른 동작을 하도록 다형성 구현**
    => **모든 것이 동일하지만 동작이 다른 것**  
    => 상속 관계에서 일어남  
    => 메서드 시그니처가 같음

- 예시
  - Dog 클래스의 `roll`을 오버로딩함
      ```java
      package ch08;

      public class Dog extends Animal{
          String breed; // 견종

          public void roll(){
              System.out.println(name + "가 바닥을 구릅니다.");
          }

        // 오버로딩
          public void roll(int times){
              System.out.printf("%S가 바닥을 %d번 구릅니다.%n", name, times);
          }
      }

      ```
  - Main() 메서드
      ```java
      package ch08;

      public class Main {
          public static void main(String[] args){
              // Dog, Cat, Animal 클래스 모두 명시적 생성자가 없으므로 기본 생성자가 추가되고 필드가 초기화됨
              Dog myDog = new Dog();
              Cat myCat = new Cat();
              myDog.breed = "진돗개";
              myDog.name = "바둑이";
              myDog.age = 3;
              System.out.printf("%S는 %S이고 %d살입니다.%n", myDog.name, myDog.breed, myDog.age);

              myCat.name = "나비";
              myCat.age = 2;
              System.out.printf("%S는 %d살입니다.", myCat.name, myCat.age);

              myDog.eat();
              // 오버로딩
              myDog.roll(2);
              myCat.eat();
              myCat.rub();
          }
      }

      ```

  - 실행 결과
      ```java
      바둑이는 진돗개이고 3살입니다.
      나비는 2살입니다.바둑이가 밥을 먹습니다.
      // 오버로딩
      바둑이가 바닥을 2번 구릅니다.
      나비가 닭고기를 먹습니다.
      나비가 몸을 비빕니다.
      ```

### 8.2.3 형변환
- 명시적 형변환 : 바꿀 자료형을 표시해 다른 자료형으로 변환  
- 묵시적 형변환 : 바꿀 자료형을 명시하지 않아도 값의 범위를 파악해 자동으로 자료형이 바뀌는 묵시적 형변환  
    => 상속 관계에서도 2가지 방식으로 형변환이 일어남

#### ✔︎ 업캐스팅
- 업캐스팅 : 자식 클래스의 객체를 부모 클래스형으로 변환하는 것, 묵시적 형변환이 됨
- 예시
    ```java
    Animal myAnimal1 = new Dog(); // Dog 클래스 객체를 Animal 클래스형의 참조 변수에 할당
    Animal myAnimal2 = new Cat(); // Cat 클래스 객체를 Animal 클래스형의 참조 변수에 할당
    ```
    - 기본 자료형의 묵시적 형변환처럼 컴파일러에 의해 **자식 클래스의 객체**가 **부모 클래스형으로 자동 형변환**됨
    - 업캐스팅되어 부모 클래스의 참조 변수에 할당되면 부모 클래스에 선언된 필드와 메서드만 접근할 수 있음  
        => 자식 클래스에 정의한 필드와 메서드에는 접근 불가  
        => 자식 클래스에 오버라이딩된 메서드는 접근 가능

- 예시 
  - 업캐스팅된 참조 변수는 부모 클래스에 선언된 필드와 메서드만 접근할 수 있음
  - 자식 클래스 중 오버라이딩된 자식 클래스 메서드에만 접근 가능
    ```java
    public class Main {
        public static void main(String[] args) {
            Animal myAnimal = new Dog();
            myAnimal.name = "바둑이";
            myAnimal.eat(); // Animal 클래스의 eat() 메서드 호출
            // myAnimal.roll(); -> 오류남, 자식 클래스의 메서드
            myAnimal = new Cat();
            myAnimal.name = "나비";
            myAnimal.eat(); // Cat 클래스의에 eat() 메서드 호출
            // myAnimal.rub(); -> 오류남, 자식 클래스의 메서드
        }
    }
    ```
  - 실행 결과
    ```java
    바둑이가 밥을 먹습니다.
    나비가 닭고기를 먹습니다.
    ```

- 업캐스팅을 하는 이유
  - 부모 클래스형 하나로 여러 자식 클래스의 객체를 다룰 수 있기 때문
  - 부모 클래스로 객체를 생성했으나 각각 객체에 맞는 메서드가 호출됨 => 다형성 구현

#### ✔︎ 다운캐스팅
- 다운캐스팅 : 부모 클래스형 객체를 자식 클래스형으로 형변환하는 것
  - 소괄호 안에 넣은 자식 클래스명을 변환하려는 객체 앞에 붙여야 함

- 예시
    ```java
    public class Main {
        public static void main(String[] args) {
            Animal myAnimal = new Dog();
            myAnimal.name = "바둑이";
            myAnimal.eat(); // Animal 클래스의 eat() 메서드 호출

            Dog myDog = (Dog)myAnimal;
            myDog.roll();

            myAnimal = new Cat();
            myAnimal.name = "나비";

            Cat myCat = (Cat)myAnimal;
            myAnimal.eat(); // Cat 클래스의에 eat() 메서드 호출
            myCat.rub();
        }
    }
    ```
- 실행 결과
    ```java
    바둑이가 밥을 먹습니다.
    바둑이가 바닥을 구릅니다.
    나비가 닭고기를 먹습니다.
    나비가 몸을 비빕니다.
    ```
- 자바에서 메서드를 호출 할 때 참조 변수를 선언한 클래스 기준으로 메서드를 찾음
  - 자식 클래스형으로 변환하면 (다운캐스팅) 하면 해당 객체에 정의된 메서드를 호출할 수 있음

### 8.2.4 super
- this : 객체를 참조할 때 사용됨
- super : 부모 클래스를 참조하는데 사용됨

#### 1. super 키워드는 자식 클래스에서 부모 클래스의 메서드를 호출할 때 사용
- 자식 클래스에서 부모 클래스의 메서드를 호출할 때 사용
- 오버라이딩 시 부모 클래스의 동일한 동작을 호출하여 추가 동작을 정의할 수 있음
  - 예시
    ```java
    package ch08;

    public class Cat extends Animal{
        public void rub(){
            System.out.println(name + "가 몸을 비빕니다.");
        }

        public void eat(){
            super.eat(); // 부모 클래스의 eat() 메서드 호
            System.out.println(name + "가 닭고기를 먹습니다.");
        }
    }
    ```
  - main() 메서드
    ```java
    package ch08;

    public class Main {
        public static void main(String[] args){
            // Dog, Cat, Animal 클래스 모두 명시적 생성자가 없으므로 기본 생성자가 추가되고 필드가 초기화됨
            Dog myDog = new Dog();
            Cat myCat = new Cat();
            myDog.breed = "진돗개";
            myDog.name = "바둑이";
            myDog.age = 3;
            System.out.printf("%S는 %S이고 %d살입니다.%n", myDog.name, myDog.breed, myDog.age);

            myCat.name = "나비";
            myCat.age = 2;
            System.out.printf("%S는 %d살입니다.", myCat.name, myCat.age);

            myDog.eat();
            myDog.roll(2);
            // 오버라이딩된 동작
            myCat.eat();
            myCat.rub();
        }
    }

    ```

  - 실행 결과
    ```java
    바둑이는 진돗개이고 3살입니다.
    나비는 2살입니다.바둑이가 밥을 먹습니다.
    바둑이가 바닥을 2번 구릅니다.
    // 오버라이딩
    // super.eat()을 통해 출력됨
    나비가 밥을 먹습니다.
    // 추가 작성한 오버라이딩된 코드를 통해 출력
    나비가 닭고기를 먹습니다.
    나비가 몸을 비빕니다.
    ```

#### 2. super 키워드는 자식 클래스의 생성자에서 부모 클래스의 생성자를 호출할 때 사용
- 자식 클래스의 생성자에서 부모 클래스의 생성자를 호출할 때 부모 클래스에 명시적으로 생성자가 있어야 함
- Animal 클래스
    ```java
    package ch08;

    public class Animal {
        // 필드
        String name;
        int age;

            this.name = name;
            this.age = age;
            System.out.printf("이름 : %S%n나이: %d%n", this.name, this.age);

        // 메서드

        }

    }
    ```

```java
}
```


#### 3. super 키워드는 부모 클래스의 필드에 접근할 때 사용
- Animal 클래스
    ```java
    public class Animal {
        // 부모 클래스의 필드
        String name = "동물";
        public void printName() {
            System.out.println("부모 클래스의 name: " + name);
        }
    }
    ```
- Dog 클래스
    ```java
    public class Dog extends Animal {
        // 자식 클래스의 필드(부모 클래스와 동일한 이름)
        String name = "강아지";
        public void displayNames() {
            // 자식 클래스의 name 필드 출력
            System.out.println("자식 클래스의 name: " + this.name);
            // 부모 클래스의 name 필드 출력
            System.out.println("부모 클래스의 name: " + super.name);
        }
    }
    ```
- main() 메서드
    ```java
    public class Main {
        public static void main(String[] args) {
            Dog myDog = new Dog();
            // 자식 클래스와 부모 클래스의 필드 출력
            myDog.displayNames();
            // 부모 클래스의 메서드 호출(부모 클래스의 name 필드 사용)
            myDog.printName();
        }
    }
    ```
- 실행 결과
    ```java
    자식 클래스의 name: 강아지 
    부모 클래스의 name: 동물 
    부모 클래스의 name: 동물
    ```

- super 키워드를 사용해 부모 클래스의 필드에 접근할 수 있음
- 부모 클래스와 자식 클래스의 필드가 이름이 같을 때 super 키워드로 구분 가능

## 8.3 추상 클래스
### 8.3.1 추상 클래스란
- 추상 : 여러 가지 사물이나 개념에서 공통되는 특성이나 속성 따위를 추출해 파악하는 작용
- 추상적 : 어떤 사물이 일정한 형태와 성질을 갖추고 있지 않은 것
- 추상 클래스 : 일반 클래스의 공통 부분을 추출해서 만든 완전하지 않은 클래스

- 추상 클래스 특징
1. `abstract`를 추상 클래스 앞에 키워드로 붙여 선언
2. 추상 메서드를 포함
    - 추상 메서드 : 메서드 시그니처(abstract 키워드 사용)만 선언하고 어떤 동작을 하는지 구체적인 내용을 정의하지 않은 메서드
    - 추상 클래스를 **상속 받은 클래스**는 반드시 **추상 메서드**를 **오버라이딩**해서 동작을 구현함 => 다형성 구현
3. new 키워드를 사용해 직접 객체 생성 불가
    - 상속받은 자식 클래스에서만 객체 생성 가능
4. 추상 메서드와 동작까지 정의된 일반 메서드를 가질 수 있음
    - 일반 메서드는 자식 클래스에서 그대로 사용하거나 오버라이딩해서 사용할 수 있음
    - 필드도 포함할 수 있으며, 공통된 상태를 정의할 수 있음

- 형식
    ```java
    [접근_제한자] abstract class 클래스명 {
        // 필드
        // 일반 메서드
        abstract 반환형 메서드명(매개변수1, 매개변수2...); // 추상 메서드
    }
    ```

- 추상 클래스를 사용하는 이유
  - 코드의 가독성을 높이고 효율성과 생산성을 향상시키기 위함
  - **같은 동작을 하는 메서드**를 다른 이름의 클래스로 여러개 정의하지 않고 **부모 클래스에 선언한 메서드를 오버라이딩**함
    - 메서드명만으로 메서드의 기능을 알 수 있어 코드의 가독성을 높임
    - 공통 부분을 미리 선언해두고 상속받아 사용하는 곳에서 필요한 동작을 직접 구현해 개발의 효율성과 생산성이 높아짐

- 선언과 구현
  - 선언 : 변수, 메서드, 클래스 등의 이름과 타입을 정의하는 것
    - 선언 자체로는 동작이 수행되지 않음
    - 변수, 메서드, 클래스 등의 정보를 컴파일러에 알려주는 역할만 함
  - 구현 : 선언한 메서드, 클래스가 실제 수행하는 기능을 정의
    - 어떤 동작을 하는지 코드를 작성하는 부분
    - 변수를 초기화하는 것 또한 일종의 구현 행위

### 8.3.2 실습: 추상 클래스 상속하기
- BankAccount 추상 클래스
    ```java
    package ch08_abstract;

    public abstract class BankAccount {
        // 필드 선언
        String accountNumber; // 계좌번호
        double balance; // 잔액

        // 생성자 (객체를 초기화하는 메서드)
        public BankAccount(String accountNumber, double initialBalance){
            this.accountNumber = accountNumber;
            this.balance = initialBalance;
        }

        // 추상 메서드 (입출금 메서드)
        public abstract void withdraw(double amount);
        public abstract void deposit(double amount);

        // 계좌 정보 출력 메서드
        public void displayAccountInfo(){
            System.out.println("계좌번호: " + accountNumber);
            System.out.println("잔액: " + balance + "원");
        }
    }

    ```

- CheckingAccount 자식 클래스
    ```java
    package ch08_abstract;

    public class CheckingAccount extends BankAccount{
        // 생성자 (객체를 생성하기 위한 메서드)
        public CheckingAccount(String accountNumber, double initialBalance){
            super(accountNumber, initialBalance);
        }

        // 오버라이딩해서 추상 메서드 구현 (출금 메서드)
        public void withdraw(double amount){
            // 출금할 금액이 존재하며 잔액보다 작거나 같다면
            if (amount > 0 && balance >= amount){
                balance -= amount;
                System.out.println(amount + "원이 출금됐습니다");
                System.out.println("현재 잔액: " + balance + "원");
            } else {
                System.out.println("잔액이 부족해 출금할 수 없습니다.");
            }
        }

        // 오버라이딩해서 추상 메서드 구현 (입금 메서드)
        public void deposit(double amount){
            if (amount>0){
                balance += amount;
                System.out.println(amount + "원이 입금됐습니다.");
                System.out.println("잔액: " + balance + "원");
            } else {
                System.out.println("입금액은 0보다 커야 합니다.");
            }
        }
    }

    ```

- main() 메서드
    ```java
    package ch08_abstract;

    public class Main {
        public static void main(String[] args){
            // 입출금 계좌 객체 생성
            CheckingAccount myChecking = new CheckingAccount("123-4567890", 100000);
            myChecking.displayAccountInfo(); // 계좌 정보 출력
            myChecking.withdraw(100000); // 출금
            myChecking.deposit(50000); // 입금
        }
    }

    ```

- 실행 결과
    ```java
    계좌번호: 123-4567890
    잔액: 100000.0원
    100000.0원이 출금됐습니다
    현재 잔액: 0.0원
    50000.0원이 입금됐습니다.
    잔액: 50000.0원
    ```

- BankAccount 추상 클래스는 은행 계좌의 기본적인 구조와 동작을 선언함
- 상속받은 Checking Account 클래스에서 구체적인 동작을 정의함
- 이 구조를 활용해 입출금 계좌 외에 일정액을 납입해 이자를 받는 적금 계좌나 예금 계좌 등 다양한 종류의 계좌를 생성하고 관리할 수 있음 => 코드의 재사용성이 높아짐
  - 각 특성에 맞는 클래스를 생성하여 추상 메서드를 커스텀함   

## 8.4 인터페이스
- 다중 상속 : 자식 클래스가 여러 부모 클래스로부터 상속 받는 것
  - 단점 : 어떤 클래스의 메서드를 가져다 써야할지 혼란스러울 수 있음
- 인터페이스 : 클래스에서 구현할 메서드들이 선언된 집합으로 인터페이스에 선언된 메서드의 동작 구현을 각 클래스에서 담당함
  - 다중상속과 유사한 기능을 제공함

- 인터페이스의 특징
1. 인터페이스는 앞에 `interface` 키워드를 붙여 선언함
2. 인터페이스에는 메서드 선언만 있고 구현은 없는 `추상 메서드`를 포함함
    - 추상 메서드에서 메서드명, 반환형, 매개변수는 정의하지만 메서드 본문의 동작은 클래스에서 구현해야함
    - 인터페이스에서 선언한 메서드는 `abstract`를 붙이지 않아도 자동으로 추상 메서드로 인식됨
3. 인터페이스는 디폴트 메서드를 포함할 수 있음
    - 디폴트 메서드 : 메서드 명 앞에 `default`가 붙으며 메서드 동작이 구현된 메서드
    - 디폴트 메서드는 인터페이스를 구현한 클래스에서 오버라이딩할 수 있음
    - 디폴트 메서드를 사용하면 구현 클래스의 기존 구조와 동작을 망가뜨리지 않으면서 새 기능을 추가 가능
    - `default` 키워드를 붙이지 않으면 자동으로 추상 메서드로 인식
4. 인터페이스는 정적 메서드를 포함할 수 있음
    - `static` 키워드를 통해 정적 메서드를 정의하고 인터페이스 이름으로 직접 호출할 수 있음
    - 디폴트 메서드처럼 동작이 구현되어 있지만 **구현 클래스에서 오버라이딩을 할 수 없음**
5. 인터페이스는 상수만 포함할 수 있음
    - 상수 : 저장한 값이 바뀌지 않는 변수
    - 인터페이스에 필드를 선언하면 자동으로 public, static, final 키워드가 붙음 
    - 상수에 접근할 때 인터페이스명을 사용함
6. 인터페이스는 접근 제한자로 `public (모든 패키지 접금)`과 접근 제한자를 명시하지 않는 `default (같은 패키지에서만 접근)`만 사용할 수 있음
    - 인터페이스에서 선언한 모든 메서드는 접근 제한자를 명시하지 않아도 자동으로 `public`으로 설정됨  
    => default 접근 제한자가 없으면 public이자 abstract로 규정됨

   - 형식
       ```java
       [접근_제한자] interface 인터페이스명 {
           자료형 변수명 = 깂; // 상수

           반환형 메서드명(매개변수1, 매개변수2 ...){}; //추상 메서드
           default 반환형 메서드명(매개변수1, 매개변수2...){}; // 디폴트 메서드
           static 반환형 메서드(매개변수1, 매개변수2, ...){}; // 정적 메서드
       }
       ```

7. 인터페이스는 추상 클래스와 마찬가지로 직접 객체 생성 불가
    - 구현 클래스에서 객체를 생성하고 객체에서 인터페이스를 자료형으로 선언 가능
    - 구현 클래스에서 `implements` 키워드로 구현할 인터페이스를 명시
    - 다른 클래스를 상속받은 상태라면 구현할 인터페이스를 부모 클래스 뒤에 추가
    - 인터페이스는 다중구현이 가능하기 때문에 구현할 인터페이스가 여럿이라면 쉼표로 구분해 작성
   - 형식
        ```java
        class 클래스명 implements 인터페이스명 {}
        class 자식_클래스명 extends 부모_클래스명 implements 인터페이스1, 인터페이스2 {}
        ```

8. 인터페이스는 인터페이스끼리 상속할 수 있음
    - 구현이 아닌 상속의 개념이라 implements 대신 `extends`를 사용함
    - 형식
        ```java
        interface 자식_인터페이스명 extends 부모_인터페이스 {}
        ```

- 추상 클래스는 필드와 메서드를 공유하고 일부 메서드를 강제 구현하게 하며 단일 상속만 가능
- 인터페이스는 클래스가 구현해야 할 동작을 정의하고 여러 클래스에서 공통된 동작을 수행하도록 강제할 수 있음
  - 한 클래스에서 여러 인터페이스를 구현하는 다중 구현 가능

- InterestBearing interface

- CheckingAccount class
    ```java
    package ch08_interface;

    public class CheckingAccount implements BankAccount, InterestBearing {
        // 필드
        String accountNumber;
        double balance;
        double interestRate;

        // 생성자
        public CheckingAccount(String accountNumber, double initialBalance, double interestRate){
            this.accountNumber = accountNumber;
            this.balance = initialBalance;
            this.interestRate = interestRate; // 이자율 초기화
        }

        @Override
        // 오버라이딩해서 추상 메서드 구현 (출금 메서드)
        public void withdraw(double amount){
            // 출금할 금액이 존재하며 잔액보다 작거나 같다면
            if (amount > 0 && balance >= amount){
                balance -= amount;
                System.out.println(amount + "원이 출금됐습니다");
                System.out.println("현재 잔액: " + balance + "원");
            } else {
                System.out.println("잔액이 부족해 출금할 수 없습니다.");
            }
        }

        @Override
        // 오버라이딩해서 추상 메서드 구현 (입금 메서드)
        public void deposit(double amount){
            if (amount > 0){
                balance += amount;
                System.out.println(amount + "원이 입금됐습니다.");
                System.out.println("잔액: " + balance + "원");
            } else {
                System.out.println("입금액은 0보다 커야 합니다.");
            }
        }

        // 계좌 정보 출력 메서드 구현
        public void displayAccountInfo(){
            System.out.println("계좌번호: " + accountNumber);
            System.out.println("잔액: " + balance + "원");
            System.out.println("이자율: " + (interestRate*100) +"%" );
        }

        public void addInterest(){
            double interest = balance * interestRate;
            balance += interest;
            System.out.println("이자 " + interest + "원이 추가됐습니다.");
        }

    }
    ```

- main() 메서드
    ```java
    package ch08_interface;

    public class Main {
        public static void main(String[] args){
            // 입출금 계좌 객체 생성
            CheckingAccount myChecking = new CheckingAccount("123-4567890", 100000, 0.02);
            myChecking.displayAccountInfo();
            myChecking.withdraw(100000);
            myChecking.deposit(50000);
            myChecking.addInterest();// 이자 계산 및 추가
            myChecking.displayAccountInfo();
        }
    }

    ```

- 한 클래스만 상속받을 수 있던 추상 클래스와 달리 입금과 출금, 계좌 정보 출력 기능을 선언한 BankAccount 인터페이스와 이자 계산 기능을 선언한 InterestBearing 인터페이스를 한 클래스에서 다중 구현할 수 있음
- 인터페이스를 사용하면 다중 상속의 이점을 누리면서 클래스를 다중 상속했을 때 생기는 문제를 피할 수 있음

    ```java
    package ch08_selfCheck;

    public class SavingAccount implements BankAccount, InterestBearing{
        String accountNumber; // 계좌번호

        double monthlyDeposit; // 매월 적금액

            this.balance = initialBalance;
            this.interestRate = interestRate;
            this.monthlyDeposit = monthlyDeposit;

            } else {
                System.out.println("입금액은 0보다 커야 합니다.");
            }
        }

        public void withdraw(double amount){

        }
    ```
