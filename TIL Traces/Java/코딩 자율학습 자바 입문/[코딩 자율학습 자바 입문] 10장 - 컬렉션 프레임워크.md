# 10장 컬렉션 프레임워크
## 10.1 컬렉션 프레임워크 개요
- 자료 구조 (data structure) : 데이터(값)을 저장하고 관리하는 방법
  - 자바의 기본 자료구조 예시
    - 배열 (Array) : 같은 자료형의 데이터를 연속적으로 저장하는 구조
      - 배열도 객체
      - 자바에서 모든 객체는 힙에 저장되고 참조로 관리됨
      - 배열을 생성하면 힙에 배열 요소를 저장하는 메모리 공간이 할당되고 스택에 생성된 참조 변수에 배열 객체의 주소가 저장됨
        - 스택의 참조변수에 있는 객체의 주소를 통해 힙 안의 값을 접근함
        - 이러한 참조를 통한 메모리 관리 방식으로 인해 배열을 객체로 취급함
      - 배열은 한번 생성하면 크기가 고정되고 나중에 데이터를 추가하기 어려움   
        => 데이터를 더 효율적으로 조작하고 관리하기 위해 자바에서 **컬렉션**을 제공함

    - 컬렉션 : 데이터를 그룹으로 묶어 하나의 객체로 관리할 수 있게 하는 자료 구조
      - 객체의 일종으로 객체를 모아놓은 데이터 집합
      - 컬렉션의 종류 : 리스트, 집합, 맵, 큐, 스택 등

- 배열과 컬렉션의 차이
  - 배열 
    - 생성할 때 크기를 지정하면 크기를 변경할 수 없고 연속 할당됨
    - 배열이 가득 찼을 때 새로운 데이터를 저장하려면 더 큰 크기의 배열을 새로 생성하고 기존 데이터를 복사해야함
    - 배열을 생성할 때 자료형을 지정되며 같은 자료형의 데이터로 구성됨
    - 인덱스를 통해 접근할 수 있지만 다른 기능은 거의 제공하지 않음
      - 데이터의 추가, 삭제, 검색, 정렬 등 직접 구현해야함
  - 컬렉션
    - 동적 크기를 가짐
    - 필요에 따라 크기를 자동으로 조절
    - 데이터의 추가와 삭제도 쉬움
    - 다양한 자료형을 지원하며 여러 타입의 객체를 담을 수 있음
    - 데이터의 추가, 삭제, 검색, 정렬 등 다양한 기능의 메서드를 제공
    - 다양한 자료구조와 알고리즘이 구현돼 있어 사용자가 필요에 따라 선택해서 쉽게 사용할 수 있음

- 컬렉션 프레임워크 : 컬렉션을 효과적으로 사용하고 관리할 수 있도록 설계된 인터페이스와 클래스의 집합
  - 컬렉션 : 데이터의 집합
  - 컬렉션 프레임워크 : 컬렉션을 다루기 위해 설계한 코드 구조이자 도구
    - 다양한 컬렉션을 손쉽게 생성하고 수정 및 관리할 수 있음
    - 자료 구조의 구현을 신경 쓰지 않고 표준화된 구조를 이용해 일관된 방식으로 작업할 수 있음

### 10.1.2 컬렉션 프레임워크의 구조
- 컬렉션 프레임워크 : 다양한 구조와 알고리즘을 표준화해 제공
  - 리스트, 집합, 맵, 큐, 스택 등 자료구조를 표준화한 인터페이스들로 구성됨

1. Collection 인터페이스
- 컬렉션 프레임워크의 최상위 인터페이스로 각 컬렉션의 공통된 동작을 정의
- Collection 인터페이스를 직접 구현한 클래스는 없지만 자식 인터페이스들이 이를 상속해 기능을 확장
![alt text](<컬렉션 프레임워크의 구조.png>)

2. List 인터페이스
- 삽입된 순서대로 요소를 저장하는 리스트 컬렉션을 정의하는 인터페이스
- 중복 요소를 허용하며 각 요소에는 인덱스로 접근할 수 있음
- 주요 구현 클래스
  - ArrayList : 배열로 구현된 클래스
  - LinkedList : 이중 연결 리스트로 구현된 클래스
  - Vetor : ArrayList와 유사한 리스트이나 현재는 잘 사용하지 않음
  - Stack : Vector 클래스를 상속받아 구현된 클래스
    - 나중에 들어온 요소가 먼저 처리되는 LIFO(Last-In First-Out, 후입선출) 방식으로 요소를 관리함

3. Set 인터페이스
- 순서를 보장하지 않으며 중복 요소를 허용하지 않는 집합 컬렉션을 정의하는 인터페이스
- 수학의 집합 개념을 생각하면 이해하기 수월
- 주요 구현 클래스
  - HashSet : 해시 테이블 구조로 구현된 집합
  - LinkedHashSet : HashSet의 변형 집합, 삽입된 순서를 유지
  - TreeSet : 이진 트리 구조로 구현된 집합, 요소가 정렬된 상태로 저장

4. Map 인터페이스
- 키와 값을 한 쌍으로 저장하는 맵 컬렉션을 정의하는 인터페이스
- 키는 중복을 허용하지 않음
- 주요 구현 클래스
  - HashMap : 해시 테이블을 기반으로 구현된 클래스
    - 키와 값의 순서가 보장되지 않음
  - LinkedHashMap : HashMap의 변형으로 삽입된 순서를 유지함
  - TreeMap : 이진 트리 구조를 사용한 맵으로 키를 기준으로 정렬됨

5. Queue 인터페이스
- 먼저 삽입된 요소가 먼저 처리되는 FIFO(First-In First-Out, 선입선출) 방식으로 요소를 관리하는 큐 컬렉션의 인터페이스
- 큐의 뒤(rear)에서 요소를 삽입하고 큐의 앞(front)에서 요소를 삭제
- 중복 요소 허용
- 주요 구현 클래스
  - ProrityQueue : 우선순위에 따라 요소가 정렬돼 처리되는 큐
  - ArrayDeque : Queue 인터페이스를 상속받은 Deque 인터페이스를 구현한 클래스
    - 큐와 스택으로 모두 사용할 수 있음
  - LinkedList : Queue 인터페이스를 구현해 FIFO 방식으로 요소를 관리할 수도 있음

6. Deque 인터페이스
- Deque(덱)은 Double-Ended Queue의 약자로 양방향 큐를 정의하는 인터페이스
- 큐의 양쪽 끝에서 요소를 추가하고 삭제할 수 있는 구조
- 스택과 큐의 기능을 둘 다 지원해 LIFO, FIFO 2가지 방식으로 데이터를 처리할 수 있음
  - Stack : 자바에서 제공하는 전통적인 스택 클래스
    - Vector 클래스를 상속받아 구현되며 LIFO 방식을 따름
  - ArrayDequeue : 더 현대적인 스택 클래스로, 스택과 큐의 모든 기능을 지원함

### 10.1.3 래퍼 클래스
- 래퍼 클래스(Wrapper class) : 기본형의 값을 객체로 변환해주는 클래스
- 자바의 자료형
  - 기본형 : 정수형, 실수형, 문자형, 논리형의 값을 저장
  - 참조형 : 객체의 위치를 나타내는 주소를 저장
- 컬렉션은 객체만 저장할 수 있으며 기본 자료형의 값을 사용하려면 객체로 변환해주는 래퍼 클래스가 필요함
- 기본형마다 대응되는 래퍼 클래스가 존재하며 기본형에 해당하는 값을 래퍼 클래스에 전달하면 해당 값을 가지는 객체로 변환됨 => java.lang 패키지에 포함됨

<br>

- 래퍼 클래스의 종류

| 기본형  | 래퍼 클래스 |
| :-----: | :---------: |
|  byte   |    Byte     |
|  char   |  Character  |
|   int   |   Integer   |
|  float  |    Float    |
| double  |   Double    |
| boolean |   Boolean   |
|  long   |    Long     |
|  short  |    Short    |

- 박싱 : 기본형 값을 래퍼 클래스로 감싸 객체로 변환하는 과정
- 오토 박싱 : 자바 5 이후부터는 래퍼 클래스로 명시적으로 감싸지 않아도 값에 대응되는 래퍼 클래스 객체로 변환됨
```JAVA
package ch10;

public class Main {
    public static void main(String[] args){
        int a = 5;
        // 명시적 박싱 => 오류 남, 자바 9부터는 Deprecated(사용 중지 권고됨)
        Integer aObj = new Integer(a);

        // 오토 박싱
        int b = 10;
        Integer bObj = b;
    }
}
```

- 언박싱 : 객체를 기본형으로 변환하는 것
- 오토언박싱 : 자바 5 이후부터는 언박싱이 자동 변환됨
```JAVA
package ch10;

public class Main {
    public static void main(String[] args){    
        // 명시적 언박싱
        Integer numObj = new Integer(10);
        int num = numObj.intValue();
        
        // 오토 언박싱
        Integer numObj2 = 10;
        int num2 = numObj2;
    }
}

```

### 10.1.4 제네릭
- Object : 모든 클래스의 최상위 부모 클래스
  - 클래스가 명시적으로 다른 클래스를 상속하지 않으면 암묵적으로 Object 클래스를 상속하게 됨
  - 클래스나 메서드를 정의할 때 자료형을 미리 정하지 않고 직접 지정하고 싶은 경우 과거엔 Object형을 사용함
  - Object형으로 변수를 선언한 경우 어떤 자료형의 객체든 참조할 수 있음
  - 다만 Object형으로 선언된 변수를 사용할 때는 **명시적 형변환**을 해야함
    - 만약 잘못된 자료형으로 변환하면 런타임 오류가 발생

  - 예시 
    ```JAVA
      public class ObjectType {
              private Object content;

              public void setContent(Object content) {
                  this.content = content;
              }

              public Object getContent() {
                  return content;

          }

          public static void main(String[] args) {
              ObjectType box = new ObjectType(); // 내부 클래스 인스턴스 생성
              box.setContent("Hello, World!");
              Integer number = (Integer) box.getContent(); // 잘못된 타입 캐스팅
              System.out.println(number);
          }
      }

    ```
  - 실행 결과
    ```JAVA
    Exception in thread "main" java.lang.ClassCastException: class java.lang.String cannot be cast to class java.lang.Integer
    ```
    - box의 형태를 Integer 형으로 변환했지만 content 필드에 저장된 값은 String 형으로 형변환할 수 없어 `ClassCastException` 예외가 발생함 => 타입 안정성이 보장되지 않음

<br>

- 타입 안정성 : 프로그래밍 언어에서 데이터의 자료형이 예상하지 못한 방식으로 변환되거나 잘못된 자료형의 데이터가 사용되는 것을 방지하는 성질을 의미함

- 제네릭 : 타입 안정성을 보장하고 코드 재사용성을 높이기 위해 자바에 도입된 기능
  - 타입 매개변수를 사용함
    - 타입 매개변수 : 인터페이스, 클래스 정의할 때 자료형을 지정하지 않고 나중에 지정할 수 있게 하는 변수
      - 나중에 사용할 때 해당 객체에 저장할 수 있는 값의 자료형을 넣음
      - 마치 메서드의 매개변수처럼 자료형을 다룬다고 하여 **타입 매개변수**라고 함
  - 형식 
    ```JAVA
    class 클래스명<타입_매개변수> {} // 클래스
    public <타입_매개변수> 반환형 메서드명(타입_매개변수 매개변수); // 메서드
    ```
  - 타입 매개변수는 주로 알파벳 한글자로 표현하는 것이 암묵적인 규칙으로 다른 문자를 사용해도 됨
    - 많이 사용하는 타입 매개변수
      - <T>(Type): 클래스나 메서드에서 가장 많이 사용하는 형태의 타입 매개변수
        - Integer, String, Double 등 다양한 참조형으로 대체할 수 있음
      - <E>(Element): 주로 List나 Set의 구현 클래스에서 요소를 나타낼 때 사용함
        - E는 각 요소의 자료형을 의미함
      - <K,V>(Key, Value): Map처럼 키-값 쌍을 다루는 자료구조에 사용함
        - K는 키의 자료형, V는 값의 자료형을 나타냄
      - <N>(Number): 주로 숫자형을 다루는 클래스나 메서드에서 사용
  - 실제 객체를 생성할 때는 자료형을 지정함
    - 형식

        ```JAVA
        클래스명<자료형> 변수 = new 클래스명<자료형>();
        클래스명<자료형> 변수 = new 클래스명<>(;)
        ```

    - 생성자를 호출하는 부분에서 자료형을 유추할 수 있으면 두번째 형식처럼 다이아몬드 연산자(<>)를 사용해 자료형을 생략할 수 있음

- 제네릭을 사용한 Box 클래스 예제
  ```JAVA
    package ch10;

    public class Generic<T> {
            private T content;

            public void setContent(T content){
                this.content = content;
            }

            public T getContent(){
                return content;
            }
            
        public static void main(String[] args) {
            Generic<String> box = new Generic<>() ; // String형의 Box 객체 생성
            box.setContent("Hello, World!"); // 문자열 저장
            String content = box.getContent(); // 형변환 불필요
            System.out.println(content);
        }
    }
  ```

  - 실행 결과
    ```JAVA
    Hello, World!

    ```
    - 제너릭을 사용하면 하나의 코드를 여러 자료형에서 재사용할 수 있음
    - 제너릭을 사용하면 저장하는 값의 자료형이 고정됨 => 다른 참조형의 객체를 저장하려고 하면 컴파일 오류가 발생하여 `타입 안전성`을 보장함
    - 형변환을 하지 않아도 돼서 코드가 간결해짐
