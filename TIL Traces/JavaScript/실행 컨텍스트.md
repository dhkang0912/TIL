# 실행 컨텍스트

- 컨텍스트 : 문맥
- 실행 컨텍스트란?
    - 실행할 코드에 제공할 환경 정보를 모아놓은 객체
    - 동일한 환경에 있는 환경 정보들을 모은 실행 컨텍스트를 콜스택에 쌓아올린 후 시행하여 코드의 환경과 순서를 보장할 수 있게 됨
    - LIFO의 구조이기 때문제 순서를 보장
    - 콜스택 내부에 쌓인 실행 컨텍스트의 정보를 통해 환경을 보장할 수 있음

```jsx
var name = 'zero'; // (1)변수 선언 (6)변수 대입
function wow(word) { // (2)변수 선언 (3)변수 대입
  console.log(word + ' ' + name); // (11)
}
function say () { // (4)변수 선언 (5)변수 대입
  var name = 'nero'; // (8)
  console.log(name); // (9)
  wow('hello'); // (10)
}
say(); // (7)
// nero
// hello zero
```

- 브라우저가 스크립트를 로딩해 실행하는 순간 모든 것을 포함하는 전역 컨텍스트가 생김
    - 모든 것을 관리하는 환경
    - 페이지가 종료될 때까지 유지됨
- 그 외에도 함수 컨텍스트가 생김
    - 함수를 호출 할 때마다 함수 컨텍스트가 하나씩 더 생김

## 컨텍스트의 4가지 원칙

1. 전역 컨텍스트가 하나 생성된 후 함수 호출 시마다 컨텍스트가 생김
2. 컨텍스트 생성 시 컨텍스트 안에 변수 객체(arguments, variable), scope chain, this가 생김
3. 컨텍스트 생성 후 함수가 실행되는데 사용되는 변수들은 변수 객체 안에서 값을 찾고 없다면 스코프 체인을 따라 올라가며 찾음
4. 함수 실행이 마무리되면 해당 컨텍스트는 사라짐(클로저 제외), 페이지가 종료되면 전역 컨텍스트가 사라짐

## 전역 컨텍스트

- 전역 컨텍스트가 생성된 후 2번째 법칙에 따라 변수 객체, scope chain, this가 들어옴
- 전역 컨텍스트는 arguments(함수의 인자)가 없음
- variable은 해당 스코프의 변수들
- 현재 scope chain(자신과 상위 스코프들의 변수 객체)는 자기 자신인 전역 변수 객체
- this는 따로 설정되지 않으면 window
    - this를 바꾸는 방법은 New를 호출하거나 bind 하는 것

```jsx
'전역 컨텍스트': {
  변수객체: {
    arguments: null,
    variable: ['name', 'wow', 'say'],
  },
  scopeChain: ['전역 변수객체'],
  this: window,
}
```

- 코드를 위에서부터 실행하면 wow와 say는 호이스팅 되며 선언과 동시에 대입됨

```jsx
variable: [{ name: 'zero' }, { wow: Function }, { say: Function }]
```

## 함수 컨텍스트

- 7번째 줄에서 say()를 실행하는 순간 새로운 컨텍스트인 say 함수 컨텍스트가 생김
- 전역 컨텍스트는 그대로 있음
- arguments는 없고 variable은 name이 있음
- scope chain은 say 변수 객체와 상위의 전역 변수 객체
- this는 따로 설정해준 적 없어서 window

```jsx
'say 컨텍스트': {
  변수객체: {
    arguments: null,
    variable: ['name'], // 초기화 후 [{ name: 'nero' }]가 됨
  },
  scopeChain: ['say 변수객체', '전역 변수객체'],
  this: window,
}
```

- say를 호출한 후 위에서부터 8~10줄을 실행
- variable의 name에 nero를 대입한 후 `console.log(name);`
    - name 변수는 say 컨텍스트 안에서 찾게 됨 ⇒ `nero`
- 그 다음 `wow(hello)` 의 경우 say 컨텍스트 안에서 wow 변수를 찾을 수 없음
    - scope chain을 따라 상위 변수 객체에서 찾게 됨 ⇒ 전역 변수
- 전역 변수에 wow라는 함수가 있어 이걸 호출

```jsx
'wow 컨텍스트': {
  변수객체: {
    arguments: [{ word : 'hello' }],
    variable: null,
  },
  scopeChain: ['wow 변수객체', '전역 변수객체'],
  this: window,
}
```

- wow 함수가 호출되어 wow 컨텍스트가 생김
- arguements는 word = `hello`
- scope chain = wow 스코프, 전역 스코프
    - lexical scoping에 따라 wow 함수의 스코프 체인은 선언 시 이미 전역 스코프로 정해져있었음
- variable은 없음
    
    ⇒ 이제 컨텍스트가 생긴 후 함수 실행
    
    ⇒ say 함수가 종료된 게 아님
    
- wow 함수 안에서 `console.log(word + ' ' + name);`이 있음
    - word랑 Name 변수는 wow 컨텍스트에서 찾으면 됨
        - word는 arguments에서 찾을 수 있음
        - name은 변수 객체에 값이 없어 scope chain에서 전역 스코프에서 찾게 됨 ⇒ name = zero
    - 이래서 최종 console 찍히는데 nero hello zero가 되는 것
    - wow 컨텍스트에 따르면 wow 함수는 say 컨텍스트와 일절 관련이 없음
- wow 함수 종료 후 wow 컨텍스트가 사라짐
- say 함수의 실행 마무리 ⇒ say 컨텍스트 사라짐
- 전역 컨텍스트도 사라짐
