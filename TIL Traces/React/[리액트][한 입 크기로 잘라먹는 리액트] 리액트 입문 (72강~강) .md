## 최적화

  - 서버의 응답속도 개선
  - 이미지, 폰트, 코드 파일 등의 정적 파일 로딩 개선
  - 불필요한 네트워크 요청 줄임

## useMemo - 불필요한 연산 방지
### useMemo란?
- useMemo : 메모이제이션 기법을 기반으로 불필요한 연산을 최적화하는 리액트 훅
- 메모이제이션 기법 : 반복적으로 수행되는 동일한 연산이 있는 경우 처음 결과값을 계산한 이후 메모리에 저장하여 동일한 연산이 나올 때 저장된 값을 불러오는 것을 의미함

### 예시 코드
#### List.jsx
- useMemo의 콜백함수에서 첫번째 인자에 메모이제이션하고 싶은 값을 입력
  - return 받는 값을 반환해줌
- 두번째 인자에는 deps를 작성, deps에 의존하여 해당 함수가 실행되고 값이 return 된다.
``` javascript
// useMemo도 deps가 변경됐을 때 콜백함수를 다시 호출해줌
  // + 콜백함수에서 return하는 값을 반환도 해줌
  // 첫번째 인자에는 메모이제이션을 하고 싶은 값을 넣어야 함
  const {totalCount, doneCount, notDoneCount} = useMemo(()=>{
    console.log("getAnalyzedData 호출")
    const totalCount = todos.length;
    const doneCount = todos.filter((todo) => todo.isDone).length;
    const notDoneCount = totalCount - doneCount;

    return {
      totalCount,
      doneCount,
      notDoneCount,
    };
    // 빈 배열이 들어가면 처음 렌더링 될 때만 계산됨, 일반 함수를 넣어서 호출했을 때는 리렌더링 될 때마다 계산되지만 이 경우에는 딱 한번만 수행하게 됨
    // todos state의 변화에 따라 콜백함수가 실행되고 값을 반환하고 싶은 경우에는 deps에 todos state를 작성한다.
  }, [todos])
  // 의존성 배열 : deps
  // 비슷한 hook : useEffect => deps가 변경됐을 때 콜백함수를 다시 호출해주는 react hook


  // 컴포넌트 return 요소 안
  <div>
        <div>total : {totalCount}</div>
        <div>done :{doneCount}</div>
        <div>notDone : {notDoneCount}</div>
      </div>
  ```

## React.memo - 불필요한 리렌더링 방지
- 리액트의 내장 함수, 메서드
- 컴포넌트를 인수로 받아, 최적화된 컴포넌트로 만들어 반환해줌
- 최적화된 컴포넌트는 props를 기준으로 메모이제이션 됨
- 부모 요소가 리렌더링되더라도 props가 변경되지 않으면 메모이제이션 되었기 때문에 최적화된 컴포넌트가 리렌더링 되지 않는다.

### 예시 코드
#### TodoItem
- 부모 요소가 리렌더링 됐을 때 해당 요소가 리렌더링할 필요가 없는 경우 React의 memo 메서드를 사용함
- 일반적으로 `export default memo(TodoItem)`와 같이 사용할 수 있음
  - 이 경우 props가 변경됐을 때만 리렌더링 됨
  - But, props가 객체인 경우 얕은 복사로 비교하기 때문에 메모리 주소가 달라져서 props의 값이 달라지지 않아도 변경됐다고 인식
    - 이 경우 두번째 인자에 콜백함수를 넣어서 props 변경 기준을 커스터마이징 해줌
    ``` javascript
      export default memo(TodoItem, (prevProps, nextProps) => {
        // 반환값에 따라, Props가 바뀌었는지 안 바뀌었는지 판단
        // T -> Props 바뀌지 않음 -> 리렌더링을 하지 말라
        // F -> Props 바뀜 -> 리렌더링을 해라
        if (prevProps.id !== nextProps.id) return false;
        if (prevProps.isDone !== nextProps.isDone) return false;
        if (prevProps.content !== nextProps.content) return false;
        if (prevProps.date !== nextProps.date) return false;

      return true;
    });
    ```
``` javascript
import "./TodoItem.css";
import { memo } from "react";

// todoItem의 경우 객체값을 받기 때문에 같은 값을 받아도 메모리 주소가 달라지기 때문에 다른 props를 받는다고 여겨져서 제대로 리렌더링됨
// 얕은 비교를 하기 때문에 객체 타입의 값은 props가 바뀌었다고 판단하게 됨
// => 이런 경우 함수 자체를 메모이제이션 하거나 memo 함수의 두번째 인자에 콜백함수를 넣어서 커스터마이징 할 수 있음
const TodoItem = ({ id, isDone, content, date, onUpdate, onDelete }) => {
  const onChangeCheckBox = () => {
    onUpdate(id);
  };

  const onDeleteBtn = () => {
    onDelete(id);
  };

  return (
    <div className="TodoItem">
      {/* onClick이 아니라 onChange로 작성한 이유는 button이 아니라 input 요소이기 때문 */}
      <input
        readOnly
        onChange={onChangeCheckBox}
        checked={isDone}
        type="checkbox"
      />
      <div className="content">{content}</div>
      {/* 문자열 datestamp를 새로운 date 객체를 생성하고 날짜 형태의 문자열로 보여지게 변환 */}
      <div className="date">{new Date(date).toLocaleDateString()}</div>
      <button onClick={onDeleteBtn}>삭제</button>
    </div>
  );
};

// 고차 컴포넌트
// 두번째 인자에 콜백함수를 넣어서 해당 콜백함수에 의해 props가 변경됐는지 여부를 확인

// export default memo(TodoItem)
export default memo(TodoItem, (prevProps, nextProps) => {
  // 반환값에 따라, Props가 바뀌었는지 안 바뀌었는지 판단
  // T -> Props 바뀌지 않음 -> 리렌더링을 하지 말라
  // F -> Props 바뀜 -> 리렌더링을 해라
  if (prevProps.id !== nextProps.id) return false;
  if (prevProps.isDone !== nextProps.isDone) return false;
  if (prevProps.content !== nextProps.content) return false;
  if (prevProps.date !== nextProps.date) return false;

  return true;
});
```

## useCallback - 불필요한 함수 재생성 방지하기
### useCallback이란?
- 리렌더링될 필요 함수가 재생성되지 않도록 하는 react hook

### 최적화를 하는 시점
- 시기 : 기능 구현을 완료하고 최적화하는 것을 추천
  - 미리 하면 동작이 제대로 안될 수도 있음
- 대상 : 꼭 최적화를 해야하는 대상
  - 대상이 되는 예시 : 유저의 행동에 따라서 개수가 많아질 수 있는 컴포넌트, 함수가 많아서 무거워질 수 있는 컴포넌트
  - 간단한 컴포넌트라면 차라리 리렌더링을 하는 게 나음
